# Doushu v2 用户呈现层

## 目标

把通用分析和专项分析改写成普通用户不懂紫微斗数也能读懂的报告。

## 用户可见结构

每个专项主题最多使用四个一级标题：

1. 先说结论；
2. 可能表现；
3. 如何判断；
4. 现在怎么做。

主路径、次路径、替代路径、成立条件、反向表现和风险等级属于内部分析标签，不要全部作为用户可见标题。
每个结构优先写成连续的完整段落。只有在确实有助于比较选择时才使用少量项目符号；不要把每个判断拆成问题清单。

## 可能性呈现

用现实状态分流：

- 如果你目前有稳定工作……
- 如果你正在换工作……
- 如果你目前有稳定关系……
- 如果你目前没有稳定关系……
- 如果你正在合作或签约……

保留有依据的可能性，但合并相近内容，不重复解释同一判断。

## 语言要求

- 先说人话，再说依据；
- 专业词第一次出现时立即翻译；
- 每段只讲一个重点；
- 建议具体到时间、行为、沟通、记录、边界或选择；
- 不把推测写成事实；
- 不用免责声明替代分析。

## 用户验证与决策引导

不要在结尾堆叠多个问题。把验证写成自然段：先说明需要用户回看哪类经历或状态，再提出最多两个关键确认点，最后说明不同答案会如何改变理解。

报告必须帮助用户思考选择，但不代替用户作决定。每个重要主题至少说明一个可继续观察的信号、一个需要核对的现实条件和一个低成本下一步。

## 专业表达审校

用户正文完成后调用 `restrained-professional-voice`。审校时执行：

1. 结论前置；
2. 删除无信息增量的分点和重复；
3. 将抽象词改成时间、行为、条件、结果和边界；
4. 区分事实、推测和待验证内容；
5. 保留健康、财务、关系和职业建议的边界；
6. 不把文字改得过度工整，不增加原分析没有的事实。

## 交付前检查

- 用户只看正文也能理解；
- 每个可能性都有识别方式；
- 每个报告都有行动建议；
- 专业依据放在附录；
- 同一判断只完整出现一次；
- 健康有医学边界；
- 事业和感情没有确定性承诺。
