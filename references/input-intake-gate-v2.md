# Doushu v2 输入询问门禁

这是排盘和分析开始前的强制输入流程。没有通过输入门禁，不得生成命盘、检索案例、进行专项分析或交付报告。

## 一、首次询问

用户未提供完整资料时，必须主动询问缺失项。不要只说“请提供出生信息”，要明确列出：

```text
请先提供以下资料，我确认后再开始排盘：

1. 历法：公历或农历
2. 出生日期：年、月、日
3. 出生时间：几点几分；如果不确定，请写大致时间范围或时辰
4. 出生时间准确程度：准确到分钟/大约时间/只知道时辰/完全不确定
5. 性别
6. 出生地：城市和国家/地区
7. 时区：不知道时可按出生地推定，但必须标记为推定
8. 是否需要真太阳时校正：需要/不需要/不确定
9. 分析需求：本命、事业、感情、健康、财务、社交或其他
10. 分析时间范围：本命、大限、未来三年或指定年份
```

如果用户已经提供部分资料，只询问缺失项，不重复询问已有信息。

## 二、输入门禁

进入排盘前必须检查：

- 日期和历法已确认；
- 出生时间已确认，或已明确记录为不确定；
- 性别已确认；
- 出生地和时区已确认或标记为推定；
- 报告方向已确认；
- 需要时间分析时，分析时间范围已确认。

任一必填项缺失：暂停并询问，不得继续排盘或生成分析。

## 三、出生时间不确定

如果出生时间不明确、存在跨时辰风险或真太阳时可能改变时辰：

1. 询问可确定的时间范围；
2. 列出候选时辰；
3. 分别说明候选时辰的主要现象、行为和经历差异；
4. 请用户通过经历对比确认；
5. 用户确认后按单盘分析；
6. 用户无法确认但明确要求比较时，才进行双盘/多盘比较，并在结果中标记不确定性。

不得自行猜测时辰，也不得把候选时辰之一当成已确认资料。

## 四、对话状态

在 `execution-manifest.json` 中记录：

```json
{
  "input_intake": {
    "status": "passed",
    "calendar": "公历",
    "birth_date": "已确认",
    "birth_time": "已确认/不确定/候选比较",
    "birth_time_accuracy": "准确到分钟/大约时间/只知道时辰",
    "sex": "已确认",
    "birth_place": "已确认/推定",
    "timezone": "已确认/推定",
    "true_solar_time_risk": "已判断",
    "analysis_scope": "已确认",
    "analysis_period": "已确认/不适用",
    "pending_questions": []
  }
}
```

`status` 只有在所有必填项通过后才能写成 `passed`。存在待询问项目时写 `pending`，并停止后续阶段。
