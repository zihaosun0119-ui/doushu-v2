# 数据复用与失效规则

准备或复用数据时读取本契约。chart_key 仅用于归档同一命盘，不足以单独证明缓存仍有效。

## 分层缓存键

键值使用规范化 JSON 的 SHA-256：对象键递归排序，日期与时间格式统一；数组保留业务顺序。将具体参数与键一起保存，不能只存哈希。

| 缓存 | 纳入键的输入 |
|---|---|
| 命盘与庙旺 | 历法、闰月、出生日期/时刻、性别、地点/经度、时区与夏令时、校时方式及修正后时刻、候选标识、排盘算法和版本、庙旺及四化规则版本、结构化源命盘哈希 |
| 大限/流年/流月 | 上游命盘键、所需层级与起止时间、换年/换月口径、运限算法和版本、fallback 算法版本及源数据哈希 |
| 案例检索 | chart_key、查询条件与状态过滤、检索算法版本、案例库内容哈希或单调递增版本 |

外部结构化命盘仍须记录来源和哈希；不能用缺失的算法版本冒充版本已确认。不适用字段显式记为不适用，缺少影响结果的键字段时，不认为缓存已验证。

## 复用条件

同时满足以下条件才复用：键相同、产物存在且 SHA-256 一致、产物数据校验通过、覆盖当前需要的时间范围。时间覆盖不足时只补足缺失范围，合并后重新校验并更新键和哈希；无法安全合并时重建该运限产物。

案例库新增、修改或删除后必须更新库版本或重算内容哈希；即使出生资料未变，也重新检索。优先使用库内容哈希，不能只依赖文件修改时间。

算法、排盘口径或出生参数变化，使命盘及依赖它的运限失效；只有案例库变化时，不重排命盘。报告文字或语言审校规则变化，只重做相关报告阶段。

## 记录与候选盘

每个数据产物保存 cache_key、key_inputs、artifact_path、artifact_sha256、generated_at、coverage 和 reused/rebuilt 原因。可放在任务数据清单中，并作为执行契约的数据证据文件登记；这是执行者必须落实的复用协议，不宣称现有脚本已自动实现缓存。

候选盘分别使用 candidate_id 和独立产物路径。未确认候选不能覆盖确认盘，候选间不共享只属于单盘的运限或案例结论。
