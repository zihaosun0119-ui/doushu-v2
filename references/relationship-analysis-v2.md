# 感情专项规则（简化版）

## 输入

先确认关系状态：单身、暧昧、稳定关系或分手/复合。状态缺失时只问这一项。

## 固定输出

### 1. 未来对象画像（partner-profile）

单身报告必须回答外貌、家庭财富层次、性格和相处模式：

- 外貌：结合夫妻宫主星、迁移宫和交友宫写脸型、眉眼、鼻梁、下颌、身材、穿衣和气质等可观察特征；不得只写“整体气质”。
- 家庭：结合夫妻宫三方四正、田宅、官禄、福德/财帛及转宫法，给出家庭资源、教育投入、居住资产、职业平台和消费结构的层次推论。
- 性格与相处：写行动方式、沟通习惯、冲突表现、关系推进和长期生活分工。

每项结论都要标明“盘面出处”和“现实核对项”。资料不直接覆盖外貌或阶层时，先用 AnySearch 检索传统判断方法，再按方法形成合理推论，并在报告列出有效链接；不再留空或只写限制语。

### 2. 相识路径（meeting-context）

按夫妻、迁移、交友、官禄、田宅和运限筛选，列出工作/项目、异地迁移、学习/兴趣等最多 3 类主路径。固定格式：

```text
来源方向 → 场合 → 触发事件 → 具体推论 → 给用户的进入建议
```

建议必须可执行，例如参加跨团队项目、职业培训、行业活动、异地出差或有产出的兴趣社群。删除空泛的“能否”“暂不支持”“不列为主要路径”等表述。

### 3. 关系时间地图（meeting-window）

按本命 → 大限 → 流年 → 流月，至少列出 10 个具体时间点；每个时间点包含农历月份、相遇场合、触发事件和关系落点。流月统一用 `monthlyList(目标年, true)`，闰月拆成前段和后段；没有流月资料时先重新读取并生成，不用泛泛的年度标签代替。

### 4. 关系底层模式（interaction-pattern）

保留一个“触发 → 反应 → 对方反应 → 结果 → 修复动作”的循环，聚焦沟通、边界、投入、承诺、时间、金钱和现实安排。

## 判断方法与来源

外貌取夫妻宫主星与迁移/交友宫形象象；家庭层次取夫妻宫三方四正、田宅和转宫后的财官；相识场合取夫妻、迁移、官禄、交友流月重叠处。AnySearch 仅用于补充“如何从传统盘面推到外貌/家境”的方法，检索后必须把来源链接和对应推理写回报告。

## 删除项

感情报告不再生成“Must-have 与 Dealbreaker”“现在怎么做”“资料边界”三个独立章节。可执行建议直接放在相识路径和时间点表中。

## 最终摘要

感情专项默认输出 Markdown 文件；不自动生成 HTML、PDF 或其他网页格式，除非用户明确指定。

```text
【核心关系需求】
【未来对象外貌与家庭层次】
【性格与相处模式】
【相识方向、场合、事件】
【6—10 个重点时间点；用户要求很多时扩展】
【给用户的进入建议】
```
