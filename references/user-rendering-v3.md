# Doushu v3 用户呈现层

## 目标

把已经完成的深入分析，改写成自然、克制、容易理解的用户正文。默认采用与分析稿严格分离的交付方式；生成用户报告前必须读取 `user-report-rewrite-contract-v1.md`。

用户正文只呈现现实层面的结论、表现、选择和行动。完整推论、盘面依据和不确定性记录放在独立分析稿，不以括号、脚注、附录或简写形式混入用户正文。

## PDF 首屏与逐月总览

PDF 首屏先给咨询者可直接使用的结论：一句话总判断、3—5 条最重要结论、当前阶段最值得关注的领域、一张行动卡、数据完整度和主要限制。不要让用户先阅读方法、星曜表或长篇推演才能知道重点。

用户要求逐月分析且流月数据为 `complete` 时，在领域分析前加入“月度总览”，按农历月份完整列出目标年份；闰月按上、下半月分别列出。每月写核心主题、2—3 个重点领域、2—4 个可观察表现、2—4 个行动、依据摘要、资料缺口。若流月数据为 `partial` 或 `unavailable`，只显示“流月数据未完成，暂不提供具体月份判断”，不得用节气月干支替代流月判断。

## 正文与推断的分离

用户正文不得写：

- 命宫、夫妻宫、官禄宫等专业术语；
- “因为某星所以……”的推演过程；
- 三方四正、四化和格局的连续解释；
- “根据命盘可以看出……”等分析提示语；
- 任何简短的术语依据、括号注释或技术性附录。

正文只写用户真正需要知道的内容，例如：

> 你更适合在职责清楚、可以处理复杂问题的环境中工作。如果长期承担责任，却没有相应权限和资源，消耗感会比较明显。

完整论证放在单独交付的分析稿，不与用户报告合并。

## 推荐表达方式

不强制每个报告使用固定的四个标题。根据内容自然组织，但通常围绕以下顺序展开：

1. 先说最重要的结论；
2. 说明可能在现实中怎样表现；
3. 说明用户可以观察或核对什么；
4. 给出现在可以做的事。

标题要像用户的问题，例如：

- 你现在最需要注意什么
- 工作上什么环境更适合你
- 关系里最容易卡在哪里
- 身体哪些状态值得提前观察
- 现在可以先做什么

不要为了完整而把每个分析步骤都变成标题。

## 可能性表达

保留有依据的不同可能，但用自然分流表达：

> 如果你目前有稳定关系，重点可能落在共同生活、时间和金钱安排；如果目前没有稳定关系，同一主题也可能表现为长期合作、客户关系或重要项目。

不要机械写“主路径、次路径、替代路径”。相近可能性合并成一段，只有确实会影响选择时才分开。

## 健康正文

健康正文要具体指出主要的脏腑观察方向，并连接到可感知的状态：

> 目前更值得提前观察的是脾胃和肝胆相关的生活状态。作息推迟、饮食不规律或压力增加时，可能先表现为食欲变化、腹胀、消化节律不稳定、眼疲劳、肩颈紧绷或情绪恢复变慢。（推断依据：疾厄宫、福德宫、命宫及八字寒暖燥湿。）

可以写“潜在的健康管理风险”，例如长期熬夜、压力累积、饮食失序、久坐和恢复不足；不能写成隐藏疾病、确诊或必然患病。

健康段落最后自然补充：如果状态持续、加重或影响日常功能，应通过正规医疗检查确认。

### 健康专项新版覆盖

健康专项正文固定按“本人身体出厂设置 → 父母家族体质溯源 → 独家专属用药与避坑指南 → 关键年份与生理拐点推测 → 定制体检与精准防守方案 → 免责与行动边界”组织。每条先给通俗结论，再写盘面出处、现实触发、可执行动作；明确父亲、母亲、本人的资料缺口。用药、保健品和体检只写风险核对点，不替代说明书、医生或药师意见，不把命盘推演写成诊断。健康专项默认 Markdown，不自动生成 HTML/PDF。

## 事业正文

事业正文重点写：

- 什么工作内容更容易发挥；
- 什么组织环境更适合；
- 什么情况下会出现责任和权限不匹配；
- 收入、成长和换方向需要核对什么。

如果存在多个选择，用一段话说明不同条件下的差异，不强行给出唯一职业答案。

## 感情正文

感情正文重点写：

- 关系中最看重什么；
- 互动和冲突通常围绕什么展开；
- 承诺是否落实到时间、金钱、城市和共同计划；
- 哪些行为说明关系正在变稳定，哪些行为说明需要重新谈边界。

不要直接写必然恋爱、结婚、分手或遇到某人，也不要替用户决定继续或退出。

## 验证与行动

不要在结尾罗列一串问题。把需要用户确认的内容自然写进正文，最多提出两个关键确认点。

行动建议控制在最有价值的两到四条，具体到观察、记录、沟通、核对、试做或就医，不写空泛的“顺其自然”和“提升自己”。

## 语言审校

正文完成后调用 `restrained-professional-voice`：

- 结论前置；
- 删除重复和机械分点；
- 把抽象词改成具体行为和现实条件；
- 保留可能性和不确定性；
- 让句子自然，不追求每段对称；
- 不增加原分析没有的事实。

## 最终检查

- 用户只看正文也能理解；
- 正文没有命理推演过程；
- 所有推断依据均保存在独立分析稿，用户正文不出现技术性括号或附录；
- 健康具体到脏腑和状态，但不越过医疗边界；
- 事业和感情提供选择依据，但不替用户做决定。

## 感情专项覆盖规则

感情专项以 Markdown 为默认交付格式，不自动生成 HTML 或 PDF。为满足对象画像和时间核验，正文可以保留简短的盘面出处与方法来源链接；必须直接写出脸型、眉眼、鼻梁、下颌、身材、穿衣、家庭资源层次、性格和相处方式。相识部分必须给出来源方向、场合、触发事件和用户进入建议。时间部分必须使用固定流月数据，至少列出 10 个公历起止窗口，括号附农历月，并在同一行写触发遇见对象的原因。感情报告不生成 Must-have、Dealbreaker、现在怎么做、资料边界独立章节。
